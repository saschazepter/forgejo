fix: search for authorized SSH public keys by exact check.  When Forgejo's internal SSH server is in-use (`[server].START_SSH_SERVER = true`), the content of public SSH keys was checked against the database with a SQL `LIKE` operation.  In SQLite installations, this `LIKE` operation is case-insensitive.  This would allow a malicious actor to retrieve the public key of a target user, craft a private key that used any public key that matched the target public key (case insensitively), and access Forgejo with that key.  Standard `ssh` access would not be possible as the private key would not pass OpenSSH's validity checks, but a crafted application could be built to access Forgejo and bypass this restriction.  The computational complexity of crafting such a public key takes less than one minute on a modern desktop.  The issue has been addressed by changing the database search to an exact fingerprint key match (a performance enhancement due to an existing DB index), and following up with an exact key content confirmation as well.
fix: check email activation in MakeEmailAddressPrimary.  Forgejo's web UI has a capability to mark an email address as the primary address of a user.  The UI restricted this to occurring on email addresses that were verified, but the backend POST endpoint did not validate that check.  In marking an unverified email address as the primary email for an account, it is possible to trick an external service relying on Forgejo as an authentication source into granting access to an unexpected external account.  The issue has been fixed by validating the email address is validated before marking it as a primary email.  Thanks to Jaeyong Lee <jay@glendalab.com> for reporting this risk and providing a patch.
fix: require tree/parent/author/committer in git object to be parsed in positional order.  Forgejo reads git commits and parses them in order to understand the structure of the commit, and its relation to other objects in the repository.  While git requires that the tree, parents, author, and committer of the commit are headers in a specific positional order, Forgejo allowed these headers to parsed in any arbitrary order.  A crafted commit could cause Forgejo to present the commit incorrectly to users, including displaying an incorrect diff.  The issue has been fixed by parsing git commits with positional awareness for these critical headers.
fix: require repo code reader unit for `/tree-list` and `/find` UI endpoints.  The `/tree-list` HTTP endpoint was missing a security check that prevented users without code reader access from interacting with the endpoint.  This endpoint can be used to retrieve the files that are present in a repository, leaking file presence information to users who were not authorized to read it.  The missing security check was added to the endpoint.
fix: implement authorization reducers in `/activities/feeds` and `/heatmap` APIs.  These APIs were accessible with repo-specific access tokens and public-only access tokens, and data from resources outside of those restrictions would be accessible.  This was fixed by implementing authorization reducers in these API calls, filtering the repositories accessible when necessary.
